\title{Communication-Matched Warp Collectives for\\
ML-KEM and ML-DSA on a RISC-V SIMT GPU}
\author{\IEEEauthorblockN{Anonymous Authors}}

\begin{document}
\maketitle

\begin{abstract}
ML-KEM and ML-DSA share Keccak and number-theoretic transforms (NTTs), yet
their useful parallelism has incompatible communication: Keccak repeatedly
reduces and permutes a 25-word state, while an NTT exchanges coefficient pairs
at power-of-two distances. We present communication-matched warp collectives
that keep both states in ordinary lane registers of an RV32 RISC-V GPU. The
instructions are stateless, use standard source vectors and single-destination
writeback, and implement fixed Keccak neighborhoods or paired NTT butterflies.
A serialized modular unit shares its routing and multiplier bank across the
16-bit ML-KEM and 32-bit ML-DSA datapaths. A 200-MHz V80 evaluation covers all
six standardized parameter sets against a matched, optimized cooperative
software mapping. Stage, shared NTT, and arithmetic reuse accelerate complete
single-request ML-KEM by \KemParameterMinOne{}--\KemParameterMaxOne{}$\times$
and ML-DSA by \DsaParameterMinOne{}--\DsaParameterMaxOne{}$\times$;
eight-request batches gain \ParameterMinEight{}--\ParameterMaxEight{}$\times$.
A separate five-point bank sweep selects two multipliers: it removes
\BankTwoNttDspSaved{}\% of NTT-hierarchy DSPs at a
\BankTwoNttPenalty{}\% NTTBF test-cycle and at most
\BankTwoEndToEndMax{}\% request penalty in middle-set Pointer controls. The results show that GPU
cryptographic hardware must be sized at request scope, not by primitive peak
throughput.
\end{abstract}

\section{Introduction}
The standardization of ML-KEM and ML-DSA gives post-quantum key establishment
and digital signatures a common deployment target~\cite{fips203,fips204}.
Although the two schemes provide different services, both repeatedly invoke
SHA-3/SHAKE and polynomial arithmetic. Efficient implementations must also
execute sampling, encoding, and, for signatures, input-dependent rejection
loops. Accelerating an isolated transform or permutation is therefore
insufficient: the useful outcome is lower latency or higher throughput for a
complete cryptographic request, including the surrounding computation.

A programmable GPU offers two levels of parallelism for these workloads.
Threads can cooperate within a polynomial or a hash state, while independent
warps process different requests. GPU implementations of Kyber and Dilithium
already exploit this structure through register reuse, kernel fusion,
batching, and cooperative scheduling~\cite{hikyber,cudilithium}. ML-Cube
further combines GPU execution and machine-learning accelerators, including
a 25-thread Keccak mapping~\cite{mlcube}. These results motivate a complementary
question for an extensible SIMT processor: which remaining work merits
specialized hardware once the software already exploits warp parallelism?

Our starting point is the cost shared by both schemes. In a historical
single-lane RV32 software study, removing the Keccak permutation bodies
reduces a complete ML-KEM-768 request by \MotivationKemKeccak{}\%, while
independently removing NTT/INTT bodies reduces it by \MotivationKemNtt{}\%. ML-DSA key generation shows the same
ordering (Section~\ref{sec:motivation}). These diagnostics identify two
reusable targets; they do not predict the benefit over optimized GPU
software. We therefore build a stronger comparison point: register-resident,
warp-cooperative Keccak and NTT kernels, with parallel sampling, encoding,
and auxiliary arithmetic enabled identically in every hardware comparison.
Our reported gains measure specialization beyond that software mapping.

The obstacle is not a lack of arithmetic parallelism but the cost of making
operands meet. Each NTT layer contains 128 independent butterflies. With
coefficients distributed across lane registers, some partners lie in the same
lane and others in lanes separated by an XOR distance. Keccak-f[1600] instead
couples 25 64-bit words through column reductions, fixed permutations, and
row-neighbor logic~\cite{fips202}. Generic shuffles express both patterns, but
introduce instructions and dependencies at each exchange. Keeping the state
in registers removes intermediate memory traffic without removing these
communication costs. The two primitives thus favor different internal
connections even when they share the same architectural register interface.

Prior hardware addresses parts of this problem at other boundaries.
RISC-V software optimization~\cite{pqrv} and finite-field instruction
extensions~\cite{alkim,bevin} reduce arithmetic cost; RISQ-V and Nannipieri
et al. add coarser polynomial operations to scalar cores~\cite{risqv,nannipieri}.
Configurable lattice processors such as Sapphire and KaLi already reuse
resources across protocols~\cite{sapphire,kali}, while KiD explicitly unifies
Kyber/Dilithium NTT multiplication~\cite{kid}. Full-protocol FPGA accelerators
also exploit request batching~\cite{highvolume}. Sharing arithmetic is therefore
established; the issue here is how shared arithmetic consumes distributed
SIMT operands and returns results through an existing GPU pipeline.

The hash interface presents a related choice. Prior work quantifies how
state transfers and sponge input/output affect hardware hashing
performance~\cite{karl}. Recent RISC-V extensions retain hash state in private
registers~\cite{horcrux}; a published patent also describes a Keccak round
executed collectively by a warp~\cite{collectivepatent}. Building on these
interfaces, we study the constraints of an RV32 SIMT core: handling 64-bit
state with 32-bit destinations, preserving per-warp dependency tracking, and
selecting the instruction granularity at complete-request scope. A faster
permutation can have little effect once sampling, sponge I/O, or polynomial
work limits execution.

We address three coupled design constraints. First, collective operations
must fit ordinary issue and writeback: an NTT butterfly logically has three
inputs and two outputs, while a Keccak step mixes values from many lanes.
Second, ML-KEM's 16-bit and ML-DSA's 32-bit coefficients require different
reductions without duplicating the entire modular datapath. Third, provisioning
all 16 pair products in parallel may waste resources when other instructions
or warps hide their latency. Neither an isolated primitive benchmark nor a
comparison against scalar C resolves these constraints.

We implement \emph{communication-matched warp collectives} in
Vortex~\cite{vortex}. The state remains in ordinary GPRs, and each instruction
replaces a fixed communication step together with its arithmetic
(Fig.~\ref{fig:thesis}). Two lanes jointly execute one NTT butterfly, compute
one Montgomery product, and each receive one result. A shared serialized
multiplier bank handles both moduli and also serves lane-local products.
Keccak exposes either three stage operations or one fused round, with
explicit low/high outputs on RV32. Every instruction returns a single
architectural destination vector and retains no cryptographic state between
instructions. We compare these register interfaces with a memory-coupled
permutation engine and size the hardware using complete requests.

The resulting Stage-plus-NTT design, including modular-arithmetic reuse,
accelerates complete single-request ML-KEM by
\KemParameterMinOne{}--\KemParameterMaxOne{}$\times$ and ML-DSA by
\DsaParameterMinOne{}--\DsaParameterMaxOne{}$\times$ over matched cooperative
software on a 200-MHz Alveo V80. All six standardized parameter sets are
covered. NTT specialization provides additional request-level gains after
Keccak acceleration. A separate bank sweep finds that two multipliers replace
16 with at most \BankTwoEndToEndMax{}\% request-cycle increase in its measured
workloads. Our contributions are:
\begin{itemize}
\item A stateless SIMT instruction interface for Keccak neighborhoods and
XOR-paired NTT butterflies, with ordinary operand tracking and one destination
per lane; controlled Stage, Round, and Pointer comparisons establish the
importance of the execution boundary.
\item A shared K/D modular unit that combines pair routing, modulus-specific
reduction, and a serialized multiplier bank. It supports forward/inverse NTT
and reuses the same arithmetic outside transforms without private polynomial
storage.
\item A complete-library, six-parameter FPGA evaluation with matched software
baselines and separate Keccak, NTT, and arithmetic ablations. Concurrency and
five-point multiplier sweeps connect primitive performance to request latency,
batch throughput, and routed hardware cost.
\end{itemize}

\section{Background and Motivation}
\label{sec:motivation}
\subsection{Shared hotspots and the scope of profiling}
ML-KEM uses degree-256 polynomials modulo $q_K=3329$; ML-DSA uses
$q_D=8380417$. Both use SHA-3/SHAKE for hashing and pseudorandom expansion,
including polynomial sampling~\cite{fips203,fips204,fips202}.
Table~\ref{tab:motivation} reports our initial single-lane RV32 SimX diagnosis:
one core, four warps of four threads, and no L2/L3. Each independent
ablation removes one primitive's body while preserving its call interface;
the reported fraction is $(C_0-C_{-i})/C_0$. The instrumented baseline and
its ablated variant share inputs and configuration. These are diagnostic
runs with intentionally invalid outputs, not accelerated implementations.

KEM has 144 permutations and 24 transforms for the selected known-answer

retries and can prevent verification from terminating. The deltas include
dependent scheduling and memory effects; they motivate specialization of
both primitives, with benefit tested on correct complete requests.

\subsection{Register placement defines the communication}
With lane $l$ holding $a[l+32k]$, $0\le k<8$, the first three forward NTT
layers exchange registers within one lane. The remaining layers exchange
lane $l$ with $l\mathbin{\mathrm{xor}}d$: $d=16,8,4,2$ for seven-layer ML-KEM,
and additionally $d=1$ for eight-layer ML-DSA. Coalesced loads and stores
surround a transform whose intermediate state remains in GPRs.

Mapping Keccak word $A[x,y]$ to lane $x+5y$ exposes column parity
($\theta$), rotate-and-gather ($\rho\pi$), and row logic ($\chi\iota$).
Each 64-bit word occupies two RV32 GPRs; rotations may need both halves even
when an instruction returns one. Figure~\ref{fig:thesis} contrasts these
neighborhoods with NTT pairs. Prior polynomial accelerators organize
computation around memory rows or accelerator-owned storage
~\cite{nttpim,bpntt,cham,zkflex}; here the architectural lane vector is the
boundary. Fixed communication can replace generic shuffles while leaving
sampling and request control on the programmable core.

\subsection{From software references to matched baselines}
Portable C provides byte-exact reference outputs and the historical diagnosis.
PQRV's optimized scalar RISC-V Keccak~\cite{pqrv} provides a separate scalar
comparison, not the denominator of the main board results. Our primary
baseline, A, uses the register layouts above with software shuffles and the
same surrounding warp optimizations as the hardware arms. B adds Keccak
Stage; C adds shared NTT; D adds both; E additionally reuses modular hardware
outside transforms. A--E isolate hardware gains under one software mapping.
Separate matched configurations evaluate Keccak granularity and
multiplier-bank size (Section~\ref{sec:evaluation}).

\section{Design and Implementation}
\subsection{Collective contract and core integration}
Figure~\ref{fig:architecture} places the units beside the integer ALU. An
instruction consumes complete source vectors and the active mask, then returns
one destination vector through the existing result arbiter. No operation
contains a pointer, writes memory, or retains architectural state after
writeback. Keccak requires a converged warp; NTT requires pair-closed masks.
Padding lanes return zero. These constraints permit static wiring and allow
different warps to interleave without saving a cryptographic context.

The decoder uses one custom opcode family and a compact function field for
operation, low/high selection, NTT direction, modulus, and XOR distance. The
scoreboard sees the same source and destination registers as the execution
unit; no implicit register or memory dependence is introduced. A collective
accepts an instruction only when its entire input vector and metadata can be
captured. It holds warp ID, destination, mask, and lane results under output
backpressure, so a stalled result cannot be paired with a later warp. This
property is especially important for a serialized NTT instruction, which
occupies several internal beats but commits exactly once.

\subsection{Keccak: stages, rounds, and RV32 halves}
For coordinates modulo five, the datapath implements
\begin{align}
C[x]&=\bigoplus_y A[x,y],\nonumber\\
T[x,y]&=A[x,y]\oplus C[x{-}1]\oplus\mathrm{rol}(C[x{+}1],1),\nonumber\\
B[y,2x{+}3y]&=\mathrm{rol}(T[x,y],\rho[x,y]),\nonumber\\
A'[x,y]&=B[x,y]\oplus(\neg B[x{+}1,y]\wedge B[x{+}2,y]).
\end{align}
The \emph{Stage} interface exposes $\theta$, $\rho\pi$, and $\chi\iota$.
Each has low/high RV32 forms returning the selected half. Six issues form
a round. The \emph{Round} interface
fuses all stages and uses a literal round index. Its low/high instructions
recompute the internal full word from identical operands, avoiding hidden
state and multi-destination writeback. Two issues form an RV32 round. A
memory-coupled engine that reads and writes the 200-byte state provides the
coarser comparison point.

Stage has two pipeline registers and accepts one operation per cycle. Round
registers parity, $\theta$, $\rho\pi$, and $\chi\iota$ in four steps and also
has initiation interval one. Its larger internal state explains why it can
improve an isolated permutation while producing little request-level gain.
For $\theta$ and $\rho\pi$, both half instructions read both old halves because
rotation carries cross the 32-bit boundary. Software therefore writes the
first result to a temporary until the second issue has consumed the old pair.
$\chi\iota$ reads one half and a warp-uniform round index. Round encodes the
index as an immediate, enabling the 24 rounds to be expanded without a table
load or branch in the permutation body.

\subsection{NTT: one product, two lane results}
For an XOR pair, pair-low lane $p$ supplies $a$ and twiddle $\zeta$; pair-high
lane $h=p\mathbin{\mathrm{xor}}d$ supplies $b$. A forward instruction computes
\begin{equation}
t=\Mont(b\zeta),\qquad (r_p,r_h)=(a+t,a-t).
\end{equation}
One product thus serves both lanes, and each lane writes its own destination.
The inverse instruction first forms a sum and difference, then multiplies the
appropriate branch. Lane-local \code{NTTMUL.K/D} handles the first three
layers, inverse scaling, ML-KEM base multiplication, and independent ML-DSA
pointwise products.

A bank of $M$ signed $32\times32$ multipliers serializes the 16 logical pair
products without changing the ISA or binary. CT and ML-DSA inverse
butterflies use $16/M$ beats; ML-KEM inverse and 32-lane scalar products use
$32/M$. The direct latency and initiation interval are $6+B$ and $B$, where
$B$ is the beat count. Operands are captured on the first handshake, lane
results are assembled by index, and backpressure freezes the serializer and
product pipeline. Pair routing, capture, and writeback are shared; only the
constant-arithmetic reductions for $q_K$ and $q_D$ differ.

The shared bank preserves each library's native residue representation rather
than converting coefficients at its boundary. For ML-KEM, operands are
sign-extended from 16 bits; a shift--add Montgomery factor and the constant
20159 Barrett product produce the forward and inverse results. ML-DSA uses the
full signed $32\times32$ product, its Montgomery inverse, and $q_D$ in the
reduction stage. Both modes therefore use the same operand capture,
multipliers, beat controller, and result assembly. Modulus selection changes
only the constant paths after multiplication. This organization lets
\code{NTTMUL.D} serve both butterfly products and ordinary pointwise products
without a second arithmetic unit.

Twiddles are explicit lane operands; there is no twiddle ROM or internal
layer counter. The paired encoding maps $(a,b,\zeta)$ and $(r_p,r_h)$ onto
two source vectors and one destination vector. Figure~\ref{fig:detail}
shows M2 assigning 16 pairs to two multipliers over eight beats.
Result assembly records lane indices and releases the vector after the final
reduction. Other warps can execute on other functional units while the
issuing warp waits on its destination dependency.

\subsection{Complete-library integration}
The native libraries retain their public APIs and byte-level
outputs~\cite{mlkemnative,mldsanative}. Their Keccak and NTT hooks select the
shared datapaths. Lane zero broadcasts primitive arguments, activates the
cooperating lanes, and resumes scalar control when the primitive returns. One-shot SHAKE
keeps its state in registers across absorb, permutation, and squeeze; an
incremental context is stored between calls. NTT kernels load eight
coefficients per lane and perform all layers without intermediate memory.
ML-DSA also reuses \code{NTTMUL.D} for ordinary pointwise products. The
ML-DSA-65 five-term matrix-vector sum accumulates in 64-bit software and
performs one final Montgomery reduction, preserving the library representation.

The leader controls allocation and rejection loops; warp kernels parallelize
candidate filtering, encoding, noise generation, and signing arithmetic.
All 32 lanes enter and leave each cooperative region together, using the
converged or pair-closed masks required by the primitive. Intrinsics name
every source and destination for ordinary compiler dependency tracking.

Full-RAM ML-DSA reserves 88 KiB per request for sets 44/65 and 160 KiB for
set 87. Leader-only allocation and reverse-order release reclaim temporaries
after every signing attempt. All six parameter sets compare keys, ciphertexts
or signatures, and shared secrets byte for byte with portable C.

\subsection{Model and RTL verification}
The SimX model mirrors RTL bank beats, pipeline latency, and result stalls.
Processor tests exercise decode, scoreboard hazards, and writeback; XRT adds
the AFU integration used by complete applications. Unit tests cover all five
XOR distances, both directions and moduli, masks, backpressure, and consecutive
warp metadata. Lane results are checked against scalar references before
transform boundary vectors and complete-library known-answer tests. Matched
SimX/XRT binaries must retire identical instruction counts with cycle gaps
below a fixed 5\% bound. All 60 single/eight-request A--E cases across the six sets pass
both models with identical instruction counts and at most
\HeadlineParityMax{}\% cycle difference. Their five board repetitions also
match the XRT instruction counts. Independent post-route cores measure each
hardware choice.

\subsection{Contributions of the Hardware Paths}
The ablation separates each hardware contribution. Across parameter sets and
one/eight requests, Stage alone gives \KemStageMin{}--\KemStageMax{}$\times$
for KEM and \DsaStageMin{}--\DsaStageMax{}$\times$ for DSA (A/B).

set 768 is within 0.2\% of D. All headline results use E. Within a matched
case, $(A/B)(B/D)(D/E)=A/E$; ratios from separate cohorts are not combined.

\subsection{Concurrency and Batch Size}
Figure~\ref{fig:scaling} separates occupancy from batch size. On eight fixed
inputs, increasing workers from one to eight raises E throughput by
\ParameterOccupancyMin{}--\ParameterOccupancyMax{}$\times$. With eight workers
fixed, extending batches from eight to 64 changes throughput to only
\ParameterBatchMin{}--\ParameterBatchMax{}$\times$ its eight-request value.
Intermediate DSA batches peak at \ParameterBatchPeak{}$\times$, so throughput
is not monotonic. Batches use synchronized waves. DSA signing retries vary by input;
extending a batch also extends its input prefix, so its curve includes both
amortization and workload variation.

\section{Conclusion}
Communication-matched collectives expose Keccak neighborhoods and NTT pairs
through ordinary lane registers, with shared K/D modular arithmetic. All six
parameter sets gain \ParameterMinOne{}--\ParameterMaxOne{}$\times$ for complete
single requests over cooperative software at 200 MHz. Independent granularity
and bank studies connect primitive timing to request benefit and routed cost.
